# 12 — Internationalisation & Bilinguisme (i18n)

> Ce document détaille l'architecture d'internationalisation de **LPI Certification Prep**, son implémentation typée sans dépendance tierce lourde, et sa stratégie de gestion des données pédagogiques bilingues.

---

## 1. Philosophie & Objectifs de Conception

Dans le cadre de la préparation aux examens du Linux Professional Institute (LPI) :
- Les examens officiels se déroulent souvent en **Anglais** (terminologie officielle, flags POSIX, messages d'erreur du noyau) ou en **Français**.
- Un candidat francophone a besoin d'explications conceptuelles claires en français, tout en devant impérativement s'entraîner sur la syntaxe et les intitulés officiels en anglais pour ne pas être déstabilisé le jour J.

### Principes d'Architecture i18n :
1. **Zéro dépendance lourde** : Pas de surcharge liée à des bibliothèques externes complexes (comme `react-i18next` ou `formatjs` volumineux). Le moteur repose sur un `LanguageContext` React natif et des dictionnaires TypeScript strictement typés.
2. **Typage Exhaustif à la Compilation** : L'interface `TranslationDictionary` garantit qu'aucune clé ne manque dans la traduction française par rapport à la version anglaise (`tsc --noEmit` échoue immédiatement en cas d'oubli).
3. **Bilinguisme Structurel des Données** : Les entités du domaine (modules, questions, flashcards, labs) intègrent nativement les deux langues (ex: `titleFr` / `titleEn`, `explanationFr` / `explanationEn`).

---

## 2. Architecture Technique (`src/i18n/`)

L'arborescence du module i18n est organisée comme suit :

```text
src/i18n/
├── LanguageContext.tsx   # Provider React, détection navigateur, persistance
├── types.ts              # Interface TranslationDictionary & type Language ('en' | 'fr')
├── translations.ts       # Dictionnaires statiques UI (enTranslations, frTranslations)
└── frenchData.ts         # Overlays de données de certification en français
```

### Le Contexte React (`LanguageContext.tsx`)
Le contexte expose un état et des utilitaires pour toute l'application :

```typescript
interface LanguageContextType {
  language: Language;                  // 'en' | 'fr'
  setLanguage: (lang: Language) => void;
  toggleLanguage: () => void;          // Bascule rapide 1-clic
  t: TranslationDictionary;            // Dictionnaire actif typé
  isFrench: boolean;                   // Booléen pratique pour les ternaires
}
```

### Cycle de Détection et d'Initialisation :
1. **Lecture du Cache Local** : Vérification de la clé `localStorage.getItem('lpi_prep_language')`.
2. **Détection du Navigateur** : Si aucune préférence n'est enregistrée, inspection de `navigator.language` :
   - Si commence par `fr` (ex: `fr-FR`, `fr-CA`) $\to$ bascule automatique en Français.
   - Sinon $\to$ Anglais par défaut.
3. **Synchronisation HTML** : Mise à jour automatique de l'attribut du document racine :
   ```typescript
   document.documentElement.lang = language;
   ```

## 3. Typage Strict (`TranslationDictionary`)

L'interface `TranslationDictionary` dans `src/i18n/types.ts` est découpée par domaine applicatif :

| Section | Périmètre d'Utilisation |
| :--- | :--- |
| `common` | Libellés génériques (Boutons, recherche, statut, badges, sauvegarde) |
| `header` | Barre supérieure, sélecteur de langue, menu de profil |
| `nav` | Navigation principale, onglets de modules, badges de cursus |
| `dashboard` | Métriques d'accueil, cartes dues SRS, matrice de compétences |
| `learning` | Explorateur d'objectifs LPI, détails des topics |
| `practice` | Examens chronométrés, options d'épreuve, review |
| `training` | Labs pratiques, simulateur d'astreinte (*Incident Response*) |
| `flashcards`| Système de répétition espacée (SRS), boutons d'évaluation |
| `glossary` | Index des commandes, fichiers de configuration, filtres FHS |
| `analytics`| Score estimé 200–800, facteurs de risque, graphiques |

## 4. Stratégie de Traduction des Données Métier

L'application distingue deux types de contenu :

### A. Les Libellés d'Interface (UI Chrome)
Gérés par `t.<section>.<clé>` (ex: `t.common.save`, `t.dashboard.startStudySession`).

### B. Le Contenu Pédagogique (Curriculum & Questions)
Pour éviter de dupliquer des milliers de lignes de questions ou de générer des incohérences, deux patrons sont appliqués :
1. **Propriétés Bilingues Jumelées** :
   ```typescript
   export interface ThematicPathStep {
     title: string;
     titleFr: string;
     summary: string;
     summaryFr: string;
     whyItMatters: string;
     whyItMattersFr: string;
     prodTrap: string;
     prodTrapFr: string;
   }
   ```
2. **Overlays Spécialisés (`frenchData.ts`)** :
   Pour les structures lourdes de certification (`frenchCertificationTiers`), un adaptateur applique une surcouche française sur les titres et descriptions officielles LPI lorsque `isFrench` est actif.

---

## 5. Comment Ajouter une Nouvelle Langue (ex: Espagnol / Allemand)

Pour étendre l'application à une 3ᵉ langue (ex: `'es'`) :
1. Dans `src/i18n/types.ts` : ajouter `'es'` à `export type Language = 'en' | 'fr' | 'es'`.
2. Dans `src/i18n/translations.ts` : instancier `export const esTranslations: TranslationDictionary = { ... }`. Le compilateur TypeScript relèvera immédiatement toutes les clés manquantes.
3. Dans `src/i18n/LanguageContext.tsx` : référencer `esTranslations` dans le commutateur.
